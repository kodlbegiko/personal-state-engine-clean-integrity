## 1. Research question

Does the exact frozen Candidate-v13 inference implementation retain semantic retrieval and abstention performance when evaluated on independently sourced, naturalistic, heterogeneous language surfaces that were not generated by Candidate-v13's synthetic benchmark framework?

The evaluation tests subject binding, relation binding, evidence eligibility, contradiction handling, temporal validity, abstention safety, evidence ranking, metadata isolation, Candidate-v2 source invariants, determinism, and robustness to lexical/discourse distribution shift.

A PASS is evidence only for the preregistered tested sources/domains/families. It is not evidence of universal real-world language understanding or production safety under arbitrary distributions.

## 4. Source-selection policy

Source discovery begins only after this preregistration exists in Git history.

Formal naturalistic cases must come from public, zero-cost, project-independent natural-language datasets or corpora with documented provenance. Selection is based only on the following pre-performance criteria:

1. public accessibility at zero monetary cost;
2. a documented license or terms that permit the intended research processing;
3. natural-language content created independently of this repository;
4. source-native structured state/slot/relation labels, dialogue-state annotations, QA evidence labels, or another deterministic ground-truth mechanism sufficient to construct gold without observing Candidate-v13 outputs;
5. coverage of at least one preregistered domain and one structural family;
6. deterministic retrievability or a reproducible source identifier/hash;
7. no known relation to this project's benchmark generator, README examples, or test fixtures.

Formal EV-B/EV-C must collectively use at least **3 independent source dataset families**. No single source dataset family may contribute more than **45%** of either formal stage.

Sources without adequate source-native or deterministic gold may be used only in EV-A infrastructure experiments and may not enter EV-B/EV-C.

### Exclusion policy

Exclude any item that:

- lacks adequate license/provenance;
- cannot be deterministically assigned gold without Candidate-v13 output;
- contains project-specific benchmark text or synthetic namespaces;
- fails contamination rules;
- requires post-hoc human label repair;
- exposes evaluation metadata to inference;
- cannot be reproduced from source ID/hash and transformation record.

If a source cannot legally be redistributed, commit only its identifier, license/terms reference, retrieval code, hashes, transformation provenance, and derived representation that is legally permissible.

## 9. Naturalistic transformation policy

Formal language surfaces must not be generated by Candidate-v13's benchmark generator and must not be template paraphrases of Candidate-v13 formal cases.

Permitted deterministic transformations are limited to operations that preserve independently sourced natural-language wording or source-native semantics:

- retain verbatim natural-language spans from eligible sources;
- concatenate adjacent source turns or source-native evidence spans when needed for discourse context;
- preserve or remove source speaker labels by a fixed rule;
- normalize encoding/newlines while retaining punctuation heterogeneity in the runtime text;
- deterministic selection of source-native antecedent/context turns;
- deterministic pairing of independently sourced distractor records for N3/N4/N9/N12;
- deterministic withholding of gold evidence to create N10, provided the runtime query remains a natural source utterance and the no-evidence label follows mechanically from candidate-set construction;
- deterministic ordering of stale/current records for N6 and mutually conflicting records for N7 when source-native timestamps/state revisions/contradictory annotations support the distinction.

Forbidden:

- synonym substitution as a naturalistic proxy;
- entity/value-only swaps on Candidate-v13 templates;
- LLM-generated paraphrases;
- hand-authored naturalistic cases tailored to Candidate-v13;
- editing a formal label after seeing Candidate-v13 output;
- dropping formal failures;
- using Candidate-v13 source code to reverse-engineer case wording.

If a required family cannot be constructed from independently sourced naturalistic wording and deterministic gold under these rules, formal execution is blocked rather than weakening the family definition.

## 10. Ground-truth construction

Every formal case must include evaluator-only:

- answerability;
- gold relevant memory IDs;
- expected subject;
- expected relation;
- temporal interpretation;
- contradiction status;
- expected abstain/retrieve state;
- source ID and transformation provenance.

Formal gold must derive from source-native structured annotations or a deterministic transformation whose correctness is mechanically auditable without Candidate-v13 output.

Before formal freeze, two independent evaluator implementations must derive/validate the key gold fields from the same source record. Required EV-A agreement:

- answerability agreement >= 0.98;
- subject/relation agreement on applicable cases >= 0.98;
- abstain/retrieve agreement >= 0.98;
- invalid/unresolved case rate <= 0.02.

Any disagreement is resolved only by the preregistered deterministic precedence rules encoded in source adapters; no Candidate-v13 output may be consulted. Failure to reach these validation requirements blocks EV-B.

## 11. Metadata firewall

Candidate-v13 inference may receive only:

1. runtime query text; and
2. Candidate-v2 returned production-style candidate records.

It may not receive case ID, stage, domain, family, answerability, gold IDs, expected subject/relation/temporal status, gold answer, dataset/source/corpus identifier, source document ID, annotator label, or transformation provenance.

Mutation test: hold legitimate runtime input byte-for-byte constant while mutating all evaluator-only metadata. Candidate-v13 output must remain byte-for-byte identical over the complete test set.

Any violation is terminal: `EXTERNAL_VALIDITY_INVALID — METADATA_FIREWALL_FAILURE`.

## 12. Candidate-v2 source invariant

Candidate-v2 is the sole candidate source. Candidate-v13 may reject, reorder, or abstain, but may not inject external memory, retrieve outside Candidate-v2's returned set, rescue non-returned evidence, or alter Candidate-v2.

Every Candidate-v13 returned ID must be a member of that case's original Candidate-v2 candidate set.

Any violation is terminal: `EXTERNAL_VALIDITY_INVALID — CANDIDATE_SOURCE_VIOLATION`.

## 13. Contamination firewall

Before formal freeze, compare EV-B/EV-C candidate surfaces against Candidate-v13 and Candidate-v12 benchmark text, repository README examples, project fixtures, and synthetic entity/value namespaces.

Required checks:

- exact string overlap;
- normalized overlap (Unicode normalization, case fold, whitespace collapse);
- token 5-gram overlap;
- entity namespace overlap;
- query skeleton similarity;
- memory skeleton similarity.

A case is materially contaminated if any of the following holds:

- exact query or memory text duplicate;
- normalized query or memory duplicate;
- known project synthetic entity/value namespace token appears in a role-bearing position;
- token 5-gram Jaccard similarity >= 0.85 against a project formal case;
- normalized query or memory skeleton similarity >= 0.92 under the preregistered skeletonizer.

Replacement policy: contaminated or invalid items are replaced **before freeze** by the next eligible item from the same stage/domain/family/class cell in deterministic SHA256 order using seed `42021`. Replacement cannot depend on Candidate-v13 output. If the reserve is exhausted, the stage is invalid: `EXTERNAL_VALIDITY_INVALID — DATA_CONTAMINATION`.

No formal case may be deleted or replaced after formal execution starts.

## 18. Anti-collapse gate

Detect and report:

- universal retrieval;
- universal abstention;
- near-universal retrieval (> 97% retrieve decisions);
- near-universal abstention (> 97% abstain decisions);
- single-class prediction collapse;
- structural-family collapse;
- domain-specific collapse.

Any universal or near-universal decision collapse fails the anti-collapse gate. Any structural family accuracy < 0.70 is catastrophic and cannot be rescued by aggregate performance.

## 25. Stopping rules

Stop immediately and do not continue formal evaluation when:

- historical provenance fails;
- source/license provenance cannot be established;
- evaluator validation fails;
- metadata firewall fails;
- Candidate-v2 source invariant fails;
- contamination cannot be resolved by the pre-frozen deterministic replacement policy;
- a required source/domain/family cell cannot reach its fixed count;
- any post-freeze mutation of result-affecting material occurs;
- one-shot ledger authorization fails.

An algorithmic threshold failure is **not** an infrastructure blocker and does not authorize a rerun.
